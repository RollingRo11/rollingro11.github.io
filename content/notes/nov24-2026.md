## AIMO Writeup Changes

### Renaming the “gaussian” probes.

As the reviewers pointed out, the 2-gaussian setup is technically linear discriminant analysis as a probe, since it’s using the log-likelihood between two gaussian distributions.

Afaik, something similar to this has been done once in the Geometry of Truth paper [(Marks & Tegmark, 2024)](https://arxiv.org/abs/2310.06824). In any case, we ought to rename the probes overall to “LDA” probes.

### RL-ing to reduce CoT length

To ensure length goes down, we can use GRPO with a length penalty + the model’s final output distribution as the “ground truth” target ([RLPR](https://arxiv.org/abs/2506.18254v1)).

To make sure this generalizes well enough, we can perform this RL on a mixture of data so long as it’s QA-based (naively):
- Wildchat/LMSys, etc.
- Math reasoning, technical QA datasets, AIME, any other non-agentic technical/scientific problems
- Creative datasets (asking the model to generate stories, etc.)
- *Mixing these QA datasets together might be beneficial to not isolate certain tendencies about certain datasets/domains.*
- I imagine that this will be easier for higher loop counts.

## Appendix

### A.1: differences between `Inkling-2-mini` and `TML-d24-varloop-research`
- **Shared KV caching**
  - By default, both models keep a separate KV cache for each loop pass (in vLLM and in HF transformers)
  - vLLM has an opt-in setting, `loop_share_cache`, that makes all passes of a looped layer use one KV cache. It's off by default, and vLLM only allows it on the `varloop` model (`configs.py:127-151`, `nvidia/attention.py:176-180, 277`).
  - It shares the cache across passes of the same layer, not across layers. The conv states stay separate per pass.
  - It changes the outputs, not just the memory use. With it on, every pass attends to the last pass's K/V for earlier tokens.
  - HF transformers has no such setting and always copies the cache per pass (`modeling_inkling2_loop.py:1355-1357`, `1404-1405`).
- **Speculative decoding**
  - the built-in drafter only works at 3 passes, for both models (`configs.py:272-277`).
  - *Would still be useful to try the chain-lens out here?*
- **Training** 
  - both models share pretraining and the *first* midtraining stage. 
  - For the rest of midtraining, varloop used 1–5 passes, sampled `1:2:6:2:1`, then it was post-trained at 3. 
  - The card warns against comparing it directly to Mini, and says it may behave oddly at loop counts other than 3.
